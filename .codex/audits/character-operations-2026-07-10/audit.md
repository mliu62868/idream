# 角色运营全流程 UX 审计

日期：2026-07-10  
范围：`/admin/content/official`、官方角色新建与详情、Visual Identity、Image Production 交接、`/admin/content/review-queue`、`/admin/content/templates`  
视角：内容运营 / 角色策划 / 视觉运营  
方法：真实页面只读走查、DOM 语义检查、关键实现与产品文档交叉验证；未创建、发布、下架或审核任何真实数据。

## 结论

当前产品具备基础 CRUD、上下架、审计原因、视觉身份版本和审核队列等后台能力，但整体仍是“角色数据库 CMS”，不是“角色生产工作台”。

综合评分：**4/10**。

| 维度 | 评分 | 结论 |
| --- | ---: | --- |
| 基础 CRUD | 7/10 | 搜索、筛选、新建、编辑、上下架路径完整 |
| 角色管理效率 | 4/10 | 卡片过大、无排序/分页/批量/负责人/完成度 |
| 创意生产能力 | 2/10 | 只有一句话 AI 辅助，缺少角色策划与分段创作 |
| 视觉资产闭环 | 3/10 | 有版本底座，但缺预览、对比、参考图管理和带上下文交接 |
| 发布可靠性 | 2/10 | 新建官方角色直接 `approved + public`，先上架后补素材 |
| 可访问性 | 5/10 | 基础语义尚可，但视觉身份表单、异步状态与筛选切换存在明显风险 |

## 运营理想任务

运营应能在一个连续工作区完成：

1. 建立角色创意 brief。
2. 生成并编辑人设、关系、开场、场景和对话样例。
3. 确立视觉身份与参考图。
4. 批量创作 cover / hero / chat 等素材并挑选。
5. 在用户视角预览角色卡、详情和首轮聊天。
6. 完成 QA 清单后定时或立即上架。
7. 上架后按表现数据维护、迭代和回滚。

当前体验把这些工作拆散在角色 CRUD、Visual Identity、Image Production、模板和审核队列中，且没有共享的“角色项目状态”和完成度。

## 真实走查步骤

### 1. 官方角色库 — 健康度：较差

![官方角色库](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/01-official-list-viewport.png)

优点：入口清晰，姓名 / 性别 / 风格 / 状态筛选可用，状态可见。

问题：

- 页面使用巨大的 4:5 内容卡，一屏只看到 4 个角色，违背项目既定的“高密度运营工具”方向。
- 当前角色全部显示字母占位图，运营无法靠视觉快速识别；同时每张卡均显示 `0 reference images`。
- 长角色名被截断，多个相似命名难以区分。
- 缺少排序、总数、分页、批量选择、负责人、更新时间、上架时间、完成度、素材健康、表现指标和快捷操作。
- 列表接口默认只取最多 60 条，UI 没有分页或“还有更多”提示；角色库增长后会产生静默遗漏。
- 筛选只保存在当前组件状态，无法分享 URL 或保存常用视图。

### 2. 新建官方角色 — 健康度：阻断级

![新建官方角色](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/02-new-character-v2.png)

优点：页面分组清楚，字段数量少，基础表单容易理解。

问题：

- **提交后服务端强制创建为 `approved + public`。** 角色尚未完成视觉身份、封面、主图、聊天素材和用户侧预览就已公开，生命周期顺序错误。
- 角色创作只覆盖姓名、年龄、性别、风格、简介和标签；没有角色定位、受众、关系、性格、背景故事、外貌细节、说话风格、边界、场景、开场白、对话样例、声音或视觉 brief。
- 没有“保存草稿”“稍后继续”“复制已有角色”“从 Starter 创建”或“导入 brief”。
- 没有预览角色卡、详情页或首轮聊天，运营看不到最终用户会收到什么。
- 底部的 `Reason (≥3)` 是审计字段，不是创作字段；直接暴露在主流程中造成理解成本。
- 固定底部操作条在较矮视口会压住当前区块，增加漏填与键盘焦点遮挡风险。

### 3. AI assist — 健康度：较差

实测输入“冷面都市女医生，夜班结束后在便利店偶遇，克制、聪明、有反差感”，系统只填充 Description 和 Tags；当前 mock 返回被原样同时写入两个字段，Tags 得到整句文本。

问题：

- AI 不是“共创工具”，只是一次性填两个文本框。
- 没有生成名称、卖点、人物弧光、对话风格、视觉方向和开场场景。
- 没有多方案、逐段重写、语气控制、长度控制、锁定字段或撤销。
- 没有结构化结果校验；模型返回格式稍有变化就会污染标签。
- 完成后没有明显的差异提示，也未看到异步结果播报语义。

### 4. 角色详情 — 健康度：一般

![角色详情](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/04-character-detail.png)

优点：状态、基础资料、版本、统计和上下架操作集中在同一详情页；编辑与查看状态区分明确。

问题：

- 详情页没有角色主图或用户侧预览，仍无法确认“这是谁”。
- 缺少角色准备度、素材缺口、最后编辑人、更新时间、待办、上架渠道和变更历史摘要。
- Stats 只有原始计数，没有时间窗口、趋势、转化率和异常提示；示例数据中 Likes 大于 Views，也没有数据健康提示。
- 编辑仅覆盖基础字段，无法维护完整人格、开场、示例对话、视觉 brief 等创作资产。
- `Open image production` 只跳到 `/admin/content/production`，不携带角色 ID；进入生产页后运营需要重新选择角色，且可能被本地草稿带到另一个角色。
- 已存在的角色预生成包组件没有挂载在当前详情流中，角色详情与素材生产之间缺少连续状态。

### 5. Visual Identity — 健康度：较差

![视觉身份编辑](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/05-visual-identity-final.png)

优点：已经有 active version、版本历史、identity prompt、negative prompt 和版本铸造底座，这是可继续演进的正确基础。

问题：

- 主要内容是原始 JSON、`createdFrom`、内部图片路径、seed 和内部确认 token，明显偏工程排障，不适合日常运营。
- 没有当前形象大图、脸部锚点、发型/体型/标志特征的可视化编辑，也没有参考图池管理。
- 新版本提交前没有“当前 vs 新版”图片对比、影响范围、关联素材数量或预计重生成成本。
- 版本历史没有可见的查看详情、恢复/回滚、质量分或一致性分操作。
- Identity prompt、negative prompt、style、seed、reason 等字段大多依赖 placeholder；DOM 中 style 下拉没有可访问名称。
- 要求运营输入 `characterId:visual-profile`，这是内部系统确认方式，不是运营语言。

### 6. 角色审核队列 — 健康度：一般，证据有限

![角色审核队列](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/07-review-queue.png)

优点：搜索、举报筛选、Saved Views、计数和逐项决策结构已经存在。

问题：

- 当前队列为空，只显示 `Empty`，没有解释、推荐下一步或最近处理记录。
- 表格没有角色图、完成度、提交来源、等待时长、优先级、风险摘要和详情预览。
- 审核者只能依赖被截断的 description，难以做角色质量判断。
- Saved View 控件在空队列中占据大量首屏空间，主任务层级失衡。
- 页面标题与表头为英文，说明文本为中文，语言状态不一致。
- 报告筛选按钮未在 DOM 证据中呈现选中状态语义；需要进一步键盘/读屏验证。

### 7. Character Starters — 健康度：较差

![角色模板库](/Users/kk/code/idream/.codex/audits/character-operations-2026-07-10/08-character-starters-v2.png)

优点：模板有独立列表、状态、范围和排序字段。

问题：

- 当前只有一个模板，且无封面，无法形成运营可复用的创意库。
- Starter 与“新建官方角色”没有入口连接；运营不能从模板开始创建角色。
- 模板字段仍然只是摘要与标签，没有真正承载人物结构、视觉 brief、场景和对话模板。
- Gender / Style 在模板中是自由文本，在官方角色中却是枚举，容易产生分类漂移。
- 直接暴露 `sort order` 数字，缺少拖拽排序或上移/下移。
- 新建模板同样默认 active，缺少草稿与预览阶段。

## 结构性问题 vs 视觉细节

### 结构性问题（先修）

1. 官方角色创建即公开，没有 draft / production / QA / ready 状态。
2. 角色策划、视觉身份、图片生产和发布不是同一个项目流。
3. AI assist 不支持结构化角色共创。
4. 角色库无法高密度管理增长后的目录。
5. 视觉身份是工程参数编辑器，缺少视觉决策界面。
6. Starter 与官方角色创建脱节。

### 视觉与交互细节（后修）

- 字母占位卡过多，首屏信息密度低。
- 长名称截断且无可见补全。
- 空状态只有 `Empty`。
- 中英文混排。
- placeholder 代替稳定标签。
- 异步结果、错误与筛选选中状态的可访问语义不足。

## 推荐目标方案：角色项目工作台

### 生命周期

`Draft → In production → Ready for QA → Scheduled / Published → Archived`

角色只有在以下完成度达标后才允许发布：

- 角色资料完整。
- 人格、关系、开场和示例对话完整。
- Visual Identity 已锁定。
- Cover / Hero / Chat 素材达到最低数量并完成选择。
- 用户侧角色卡、详情和首轮聊天预览通过。
- 发布信息与时间已确认。

### 新建流程

1. **Brief**：定位、受众、关系、核心反差、内容目标。
2. **Persona**：姓名、背景、性格、说话方式、关系、开场、样例对话。
3. **Visual Direction**：外貌、风格、服装、场景、参考图和身份锁定。
4. **Asset Pack**：进入已预选当前角色的图片生产工作台，创作并选择 cover / hero / chat。
5. **Preview & Publish**：三种用户视图预览、完成度清单、定时或立即发布。

每一步支持：保存草稿、AI 提供 3 个方案、逐字段重写、锁定已确认字段、版本对比和返回继续。

### 角色库

默认改为高密度表格或可切换视图，列出：

- 缩略图、角色名、负责人、生命周期状态。
- 完成度与缺失项。
- Visual Identity 版本与一致性。
- Cover / Hero / Chat 素材数量。
- 上架状态、更新时间、近 7 天表现。
- 快捷动作：继续制作、预览、复制、定时发布、下架。

支持服务端搜索、排序、分页、批量操作、Saved Views 和 URL 可分享筛选。

### 角色详情

采用工作区标签：

- Overview
- Persona
- Visual Identity
- Assets
- Preview
- Performance
- History

顶部固定显示：角色缩略图、生命周期状态、完成度、负责人、最后保存、主要下一步。

### Visual Identity

- 将 JSON 折叠到 Engineering details。
- 用图片 + 可编辑特征卡展示脸、发型、体型、标志特征和风格。
- 可增删锚点图与参考图，并显示来源和使用范围。
- 新版本先生成对比样张，再决定激活。
- 版本历史提供预览、质量分、差异、回滚和受影响素材数。

## 优先级

### P0：修正运营闭环

1. 新建角色默认 draft，发布成为独立动作。
2. 增加角色完成度和发布门槛。
3. 新建页升级为 Brief → Persona → Visual → Assets → Preview 的分步工作区。
4. 角色详情到 Image Production 携带并锁定当前 `characterId`。
5. 角色库切为高密度表格，补服务端分页、排序和总数。
6. Visual Identity 隐藏工程字段，补当前形象、参考图和版本对比。
7. AI assist 返回结构化分区与多方案，逐字段可重写。

### P1：提升规模化运营效率

1. 负责人、协作状态、批量操作和 Saved Views。
2. 定时发布、复制角色、地区/语言版本。
3. Starter 一键带入官方角色项目，并版本化模板。
4. 上架后数据趋势、质量告警和素材迭代建议。
5. 审核队列的图片预览、等待时长、优先级和详情抽屉。

## 可访问性风险

- Visual Identity 的多个字段缺少稳定 label / aria-label。
- 异步 AI assist、保存、错误和完成状态缺少明确的 live-region 证据。
- Report filter 需要补 `aria-pressed` 或单选语义并验证键盘操作。
- Sticky footer 在矮屏和放大场景可能遮挡表单与焦点。
- 小号浅灰说明文本、仅边框变化的 focus 状态需要做对比度与键盘可见性验证。

本次不是完整 WCAG 审计，未覆盖读屏器、200%/400% 缩放、移动端重排和完整键盘路径。

## 证据限制

- 为避免修改业务数据，本次没有真正创建、编辑、发布、下架、铸造 Visual Identity 或提交审核决定。
- 审核队列为空，因此无法验证行级详情与决策弹窗的完整视觉表现。
- AI assist 使用当前 mock provider，暴露的是契约与结构化处理问题，不代表最终模型文案质量。
- 截图以桌面视口为主；响应式和辅助技术需要独立验证。
