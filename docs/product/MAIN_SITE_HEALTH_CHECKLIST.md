# iDream 主站产品体检清单

编制日期：2026-09-13。用途：下一轮以 Chrome 为主，检查主站功能是否完整、用户流程是否成立、业务逻辑是否正确。

**这是待执行的验收清单，不是已通过的体检报告。** 完整范围包含 PRD 的阶段 A、B；阶段 C 的优化单独记录。当前没有入口的目标功能也保留在清单内。检查结果只能由所测版本的实际行为和证据填写。

## 1. 从第一性原理确定检查范围

用户购买和使用的是“与角色展开故事并保有成果”的能力。页面只是入口；一次任务必须同时回答：我在和谁互动、我能做什么、现在处于什么状态、需要付出多少、结果在哪里、失败如何继续、谁能看到、以后还能否使用。

| 用户价值 | 必须闭合的链路 | 不可缺少的验收结果 |
| --- | --- | --- |
| 找到合适的角色 | 发现 → 筛选 → 详情 → 开始互动 | 卡片承诺与角色身份、开场和实际能力一致 |
| 创造想象中的人物 | 描述 → 完整资料 → 形象/声音 → 私有保存 → 可选发布 | 输入不丢；私有即可使用；公开由明确操作决定 |
| 持续展开故事 | 对话 → 场景/记忆 → 修订 → 回访 | 保持身份、说话人和事实；用户可纠正、暂停和删除 |
| 创作和拥有作品 | 报价 → 图片/编辑/增强/视频/声音 → 交付 → 管理 | 真正可看、可听、可下载；来源明确；不重复收费 |
| 分享与创作者经营 | 发布 → 发现 → 互动/Remix/购买 → 收益 | 可见性、作者归属、授权、收益和撤下相互一致 |
| 安心购买和求助 | 权益比较 → 支付 → 激活 → 到期/续购 → 客服 | 费用透明；未知可查询；旧资产保有；问题有回执 |

因此每个功能都检查六个维度：**入口与可发现性、输入与权限、真实执行、持久化结果、失败恢复、跨页面一致性**。页面打开、按钮变色、HTTP 200、生成非空文本都不能单独代表通过。

### 1.2 已定边界与容易误判的地方

- iDream 面向成年人；保留 18+ 门槛、角色年龄 ≥18 和既定 mock 的 underage/minor/csam 拦截。不因 `MODERATION_PROVIDER=mock` 或未启用 `safety-gateway` 判缺口，不新增审核政策。第三方年龄验证与自助确认分别验收。
- 日常角色与素材走基础自动检查、准备和显式发布，不恢复人工批准关卡。举报、申诉、异常处置仍需闭环。
- Main PostgreSQL 是产品历史、交付和计费权威；Chat 的执行/记忆派生证据不能代替 Main 事实。不沿用旧检查计划中的 Chat 数据库架构。
- 加密货币、一次性预付周期访问、不自动续订；计划变化不改变基础人格或记忆质量，不锁回已有历史、已交付媒体或已购作品权利。
- 图片、视频、语音片段、双向通话分别验收。Generate 视频可用不等于 Chat 视频可用；片段播放不等于通话。
- 当前五步 Create 按六类任务证明等价，不为凑步骤数判失败；Catalog 数量是历史对标线索，还要核对语义与实际使用。
- 旧覆盖记录将群聊、Comic、主动消息等列为缺口，而本次工作区已出现相关入口/代码。执行时核对实际状态，不能照抄“未实现”，也不能因有代码提前签发。
- H3 等路线按被测版本实际发布配置判断；停用新生成不应删除历史。未发布目标保持缺口，正确隐藏入口只通过“关闭态”检查。
- 本文不引入聊天历史导出、自动续费、多语言等未获明确契约的新承诺；如页面已经提供相关入口，再补相应契约和测试。

经济规格中的年卡语音总分钟与滚动 30 天窗口、日消息“自然日滚动”等措辞，执行前须核对当前权益快照、计量窗口和重置说明。不能自行猜成每月一次发放或滑动 24 小时；发现冲突要留作契约澄清，不能用代码现状直接推翻需求。

### 2.3 证据等级与判定

每行的“证据”是完成签发的最低要求，可组合：

- **B（浏览器）**：操作前后截图/录像、URL、用户身份、刷新回访；媒体要实际放大查看、播放/听音或下载后打开。
- **N（网络）**：Chrome DevTools 中与本操作对应的请求、响应、状态、关联 ID 和时序；失败也留证据。HAR 和截图清除 Cookie、验证码、恢复码、私有状态链接和支付秘密。
- **P（持久化）**：由现有只读诊断、受授权后台或数据查询核对 Main 记录、交付和账本。仅刷新与余额变化不足以证明没有重复执行、没有重复收费。
- **Q（体验质量）**：把输入承诺与文本、图像、声音、视频逐项对照；记录具体不符，不能用模型自评或“文件能打开”替代。
- **O（外部/运营）**：邮件或验证回调、真实支付确认、运营回复/发布/撤下/结算等依赖。客户端模拟不能冒充这些事实。

用例执行结果使用 `NOT_RUN / PASS / FAIL / BLOCKED / NA`。`BLOCKED` 必须写明依赖和继续条件；`NA` 必须引用已确认的不适用条件，不能用于排除完整目标。组合用例任一子项失败就不能整行 PASS，必要时追加子编号。

另记能力覆盖：`待确认 / 未交付 / 部分交付 / 条件关闭 / 可验收`。例如视频关闭：关闭态可 PASS，生成用例可 BLOCKED，视频完整目标仍未通过。证据不足保持 NOT_RUN/BLOCKED，不猜测缺陷。确认的问题另按 [分诊状态](../agents/triage-labels.md) 建本地事项，不能把执行结果当作 issue 状态。

本清单不授权下一轮充值、转账、公开发布或不可逆删除；这些步骤先准备具体对象和结果预期，按届时授权执行。已授权的本地真实模型/生成请求使用最低充分次数。不能执行的步骤保留 BLOCKED，不能删去。开发/测试夹具与模拟成功均标明验证层级。

| X01 读取失败 | 先成功加载，再阻断该读请求并刷新；另测初次失败 | 同范围旧快照明确 stale；初次失败显示 error，不伪装空库/零余额；所有列表、Profile、Catalog |
| X02 写入结果未知 | 提交后断响应，保留服务端可能已接纳，再刷新/重登查原请求 | pending/unknown 不等于失败；不自动另发付费动作；Create、Chat、Generate、checkout、工单 |
| X03 双击和重放 | 同按钮连点；同请求完成后重复回访；需服务端重放用受控辅助 | 幂等键/请求归属保持，账本和交付唯一；与用户明确的新动作区分 |
| X04 竞争最后额度 | 两标签用同账号在仅够一次时提交两项合法任务 | 至多接纳余额允许的请求；拒绝项不入队，无负余额 |
| X05 旧响应晚到 | 慢网切查询/角色/模式/账号后允许旧请求返回 | 不跨范围显示数据、完成提示或可点击旧动作 |
| X06 登录失效 | 填完表或任务处理中让 session 失效，再提交/回访 | 说明并回登录；本人草稿/原任务可恢复，不自动重做收费动作 |
| X07 任务期间资格变化 | 已接受后计划到期/offer 改版/角色改版，新开一项比较 | 旧请求依冻结承诺，新请求用当前资格；不能改旧价格或身份 |
| X08 取消与完成竞态 | 任务近完成时取消；重复取消后刷新 | 只有一个权威终态；已交付不一边展示成功一边错误全退 |
| X09 部分交付 | 批量图/多 scene 中只交付部分，保留每个子结果 | 不将全部标成功/失败，退款与实际未交付份额相符 |
| X10 媒体访问失败 | 阻断缩略图/文件、使用过期签名、下载中断再重试 | 可区分预览失败和生成失败；刷新授权可恢复，不新扣费 |
| X11 外部回调延迟/重复 | 核验/支付/结算回调未到、重复到、过期到 | 客户端不自行完成；重复不授予多次；原订单有查询入口 |
| X12 跨账号对象访问 | B 用 A 的已知测试 ID/链接读或操作私有资产/账单/工单 | 服务端拒绝，无内容泄露；测试仅用本轮受控对象 |
| X13 公开状态变化 | 发布→私有/撤下，访客已开详情/搜索/分享页再刷新 | 发现与详情最终一致；缓存不能持续越权；既有合法资产访问单独保护 |
| X14 通话/主动消息后台行为 | 断网、休眠、安静时段、关闭 opt-in、关页后检查 | 不继续录音/多路计时/超频主动生成；客户端挂起不等于任务失败 |
| X15 删除与后台工作交错 | 专用账号有排队任务/记忆维护时删除，再观察生命周期 | 不复活账号/记忆，不向被删除账号追加新可见内容，清理与保留记录可对账 |

每个写操作至少执行一次取消/校验失败、重复提交、刷新核对；高成本与隐私关键操作加 X02/X04/X07/X12。无需把所有故障笛卡尔积施加到每个静态页，但省略的高风险组合必须列明。

## 7. 真实质量验收样例

使用虚构成年角色和无敏感信息的场景，避免为验证质量生成高风险内容。每个样例先保存期望，再查看结果，失败不能事后改标准。

| 样例 | 输入/操作 | 逐项判断 |
| --- | --- | --- |
| Q01 身份与说话人 | 给角色一个职业/语言习惯，让用户说“我还没决定出门”并继续两轮 | 职业与表达保持；不把用户未做动作写成已做，不抢用户决定 |
| Q02 精确事实与关系记忆 | A 会话给虚构物件标签 `LUMEN-742`，说明在蓝色窗台；B 会话盲问；随后纠正位置 | 完整标签、所属对象、正确新位置；额外改字也记录不通过，不只判断大意 |
| Q03 场景到图片 | 明确“雨夜室内，白杯右侧是绿色笔记本”，再请求画面 | 夜色/室内/雨/物件左右关系/角色身份逐项核对，不能用传入 Scene 就判像素正确 |
| Q04 局部编辑 | 对 Q03 原图要求“仅将白杯改红，保持笔记本、构图和人物” | 源图正确、目标变化、非目标保留分别判断；附带重绘如实列出 |
| Q05 声音与视频 | 试听完整台词；播放默认视频全部时长并拖动 | 内容完整、音色稳定、无爆音/长静音；视频无身份漂移/叠影/跳变；可选音轨符合承诺 |
| Q06 体验覆盖 | 五类核心样板，加 anime/中文/长对话/真实跨日中尚未覆盖维度 | 各维度分别报样本与结果，不把英文 realistic 的即时样本外推为全面质量合格 |

文本正确、Main 记忆来源正确、检索命中正确、最终模型回答正确是四件事。真实质量失败必须保留原输入、版本和产物；后续独立成功不能覆盖旧失败或拼接为同一条成功旅程。

## 8. 关键不变量与辅助对账

这些项目以 Chrome 发起和消费任务，再用 N/P/O 证据补齐；只看页面无法证明时明确保留未验证。

| 不变量 | 必须核对的事实 |
| --- | --- |
| 一次真实意图只产生一次有效副作用 | user/session/Turn/request/attempt/effect/asset/delivery 与 ledger 关联；transport 重连不等于新意图 |
| 钱与交付一致 | 期末币余额 = 期初 + 唯一入账 + 唯一退款 − 唯一预留/支出；成功结算不再额外扣一次；部分退款对应未交付份额 |
| 费用单位一致 | dreamcoin、现金原币、语音分钟、日消息额度分别核对，不能混算成另一份图片/视频配额 |
| 接受条款不可漂移 | 已接受 quote、offer、角色/声音/视觉版本、源图和用户方向固定；新配置仅影响契约允许的新任务 |
| 作品属于正确的人 | 资产所有者、可见性、合集/Remix 来源、被分享范围与买家权益一致；知道 URL 不等于有权限 |
| 记忆来自有效来源 | Main 有效原文与修订/删除、关系 scope、关闭/清除时间边界、派生状态和检索结果相互一致 |
| 历史权利持续成立 | 到期/停用只限制新能力，已交付/已购内容可回看下载；安全处置/用户删除按明确契约单独判断 |
| 公共承诺有真实依据 | published/Serving/CMS 状态、活动有效期、能力门禁与前台一致，未知指标不伪造，测试数据不算真实经营成绩 |

真实媒体证据至少记录 provider、model/workflow、规格、request/attempt/artifact/delivery、耗时、报价/净扣/退款，以及实际图像/音视频。没有暴露在 UI 的内部 ID 放报告，不要求塞进日常产品页面。
