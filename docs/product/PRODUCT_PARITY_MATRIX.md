# iDream 产品对标与验收矩阵

更新日期：2026-10-05

本表把用户目标映射到需求、故事、证据与退出条件。目标来自 [PRD](PRD.md)、[功能地图](ProductFeatureMap.md)、[9 月 1 日公开快照](../research/OURDREAM_PRODUCT_PARITY_SNAPSHOT_2026-09-01.md) 及 [9 月 5 日复核](../research/OURDREAM_PRODUCT_REVIEW_2026-09-05.md)。竞品观察是带日期的任务基线，不是实时 Catalog 或 iDream 实现状态。

实现、原失败与运行范围从 [覆盖记录](CURRENT_FUNCTIONAL_COVERAGE.md) 按域查找，未完成工作只在 [剩余工作](REMAINING_WORK_EXECUTION_PLAN.md) 维护。本文维护完整验收目标；支付、年龄、合规、AF-03 和公开生产不能由本机或范围排除的运行记录代验。

## 判定规则

对标关系与交付状态是两个维度：

- `matched`：观察范围内的能力与任务结果匹配；`equivalent`：组织不同，但有逐项等价证据；`intentional_divergence`：已明确记录的自主产品选择；`pending`：仍有差距或证据不足。前三项不能替代交付状态。
- 交付状态按能力记录：未实现、部分实现、受控本地验证、受条件限制、公开生产认证、未复核。每条认证注明范围、source revision、日期、环境与证据；不为混合域强贴单一“已完成”。
- 下面是域级验收入口，不是每个按钮和 Catalog 项的最终签发。没有逐项判定的域保持 `pending`；不能抹掉域内已有的局部成功，也不能把局部成功外推为全域完成。支付方式、资产到期权利等已定偏离单独记录，不能用偏离掩盖未交付能力。
- 条件发布只通过相应关闭态用例；完整目标仍需真实输入、权限、执行、质量、交付/持久化、成本和恢复证据。OurDream 的组织方式可以不同，用户结果和必要控制不能丢失。

### 逐功能与 Catalog 项如何留下判定

域级表用于导航；实施或验收时在本地运行报告按下列字段逐项记录，汇总入口仍是当前覆盖，不再建立第二份运行台账：

| 字段 | 必须回答 |
| --- | --- |
| 目标与追踪 | 对应 PRD、US、清单/旅程 ID；用户要得到什么结果，输入与权限是什么 |
| 对标来源 | 观察日期、公开/登录态/营销声称、页面或保存材料；未知不猜成已确认能力 |
| 差异判定 | matched/equivalent/intentional_divergence/pending；字段、控制、语义、数量和容量分别比较，明确产品理由 |
| 实现与适用条件 | canonical 代码位置，已发布 Catalog/能力/模型/权益条件；未实现与条件关闭分别记录 |
| 交付证据 | 实际 source/service revision、时间/环境、正常/失败/恢复/权限/质量、request/attempt/artifact/delivery 与账本引用 |
| 结论与继续条件 | 所证明的最小范围、未执行/失败项、原证据位置与下一步；判定人/时间，不能重标旧报告 |

创建目录、聊天档位、presets、图片批量、视频 scenes/时长/比例/质量和公开页面族，全部按 [功能地图 §1.1](ProductFeatureMap.md#11-带日期的公开广度基线) 逐维度比较。相同数量不能证明相同语义；最低充分真实样本不能证明全容量。

## 已明确的自主选择

| 项目 | 判定 | iDream 决策与理由 |
| --- | --- | --- |
| 支付方式与续期 | intentional_divergence（产品决策，交付待验收） | 加密货币、一次性预付周期访问；按自身支付能力提供透明续购，避免伪造自动续订 |
| 到期后的历史与资产 | intentional_divergence（产品决策，逐路径验收） | 保留已交付/已购资产访问；不通过锁回用户作品促进续购 |
| 套餐与角色身份 | intentional_divergence（产品决策，逐能力验收） | 套餐购买资源与高级能力，基础人格和记忆质量保持一致 |
| ASR支持范围 | intentional_divergence（2026-10-05产品决策，英语质量独立验收） | 草稿输入与Call识别仅支持英语；模型的多语能力不成为产品承诺，TTS按实际provider独立判断 |
| 创建分步与目录 | pending（拟等价，待逐项证据） | 五步可承载六类任务，但仍需逐项字段、目录语义和恢复验收；不要求仅为外观相似拆成六页 |
| 日常发布 | intentional_divergence（产品决策，运行证据见覆盖记录） | 基础自动检查后准备并显式发布，无日常人工批准；保留异常、举报和申诉处理 |
