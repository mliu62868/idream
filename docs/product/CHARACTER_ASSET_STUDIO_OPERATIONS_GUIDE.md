# Character Asset Studio 运营手册

更新日期：2026-09-09
适用角色：角色运营与发布负责人
入口：`/admin/characters/{characterId}?tab=assets`
技术参考：[角色素材与发布权威](../architecture/16-character-asset-studio-authority.md)

## 核心流程

创建角色 → 生成或上传图片 → 选择采用 → 预览 → 发布。

日常角色和素材不设人工审核关卡，不要求评分、质量勾选或先批准再采用。选择一张图片就是运营对内容和用途的判断。系统继续检查角色年龄至少18岁、基础自动拦截、文件可用性、角色归属、真实来源和发布快照。用户举报、申诉与违规处置保留；历史人工决策保留为记录，不再决定日常图片能否采用。模型评估中的实验评分仍属于技术工具。

## 创建与设定

1. 填写成年角色资料、外观、人格与开场，确认后创建私有草稿。
2. 成功后直接进入图片工作区，生成首张肖像；也可以在身份工具中使用已有身份图。
3. 选择「设为角色身份」建立视觉身份与参考集，同时采用为草稿主图。无需先填写审核表。
4. 修改角色设定会生成新内容版本；历史版本与已发布快照保留。Soul 页的技术内容默认折叠。

用户提交公开或不公开列出的角色，在基础自动检查通过后直接进入发布准备。它不自动成为线上角色。历史待审角色可以通过工作区的「准备发布」恢复入口继续，系统会重新执行自动检查。

## 图片与展示位

图片库集中保存生成和导入的图片，搜索覆盖整个库；「加载更多」可浏览较早素材。图片归档会从普通库中隐藏，归档前系统检查所有正在使用它的引用，整组操作全部成功或全部拒绝。

- 肖像：保证脸部清楚、身份容易辨认，适合发现卡片与头像。
- 详情大图：呈现人物与场景，构图适合角色详情。
- 聊天图片：自然、亲近，符合角色的开场语境。

三个展示位必须使用三个不同的可用图片。运营直接在展示位选择图片，Main 重新校验来源并记录草稿版本；选择不改变线上内容。不合适的图片可以不采用，或在解除依赖后归档，不必逐张填写拒绝结果。

生成时选择的肖像、详情或聊天构图只是创作起点，不会把图片锁在对应展示位。与上传图片一样，通过检查的生成图片可从角色图片库选择到任一合适的展示位；同一张图片不能同时占用两个展示位。调整展示位不重新生成、不复制素材，也不改写原生成请求，发布版本继续保留它的精确来源。建立身份的首张图片仍须与当前固定的视觉身份和参考集相符。

生成失败时保留已完成素材与请求记录。结果不确定时使用原请求的恢复入口，不连续发起新请求。只有明确可重试的失败才重试；来源身份变动时按页面提示重新生成，不伪造来源记录。

等待共享 GPU 与实际生成分别计时。等待期间可刷新查看同一任务，不会产生新的生成调用；同用途任务进行中时不能重复提交。若系统曾自动按超时失败结算，之后收到原任务的有效成功产物，生成任务页会在没有实际退款时提供恢复采用入口。该操作恢复原产物和素材批次，保留之前的失败记录；已经实际退款或由运营确认失败的任务不会自动改为成功。

## 视频与声音

视频从当前采用的角色图片选择来源。生成中会显示真实执行阶段；刷新页面仍能继续查看原任务。完成后直接播放与使用，无需人工批准。图片、视频、声音的最近生产记录使用一致的执行状态；未知结果显示需要核对，不伪装为仍在正常生成。

声音可以使用系统声音并试听，低频身份与克隆工具保留在相应工作区。采用声音、试听成功与用户聊天交付是不同事实。

## 预览、发布和退出

预览展示 Main 的真实卡片、详情、开场与聊天图片；没有虚构的五轮 QA 占位任务。草稿预览明确区别于线上版本。三个展示位缺失、文件不可用或重复时，应修正后重新打开预览，不能用主图悄悄替代其它展示位。

点击发布会固定当前内容、身份、参考集与图片，校验成功后才更新线上 Serving。准备成功但发布失败时，可以继续原发布，也可以「放弃待发布版本」，保留历史后重新编辑、准备和发布。

- 未上线草稿：可以归档，之后恢复为草稿；不删除设定和素材。
- 暂停角色：可以直接退出运营，无需先恢复上线。
- 已上线角色：按页面的暂停、恢复或回滚操作处理。历史版本保持不可变。
- 旧预览链接：Serving 版本或发布指针变化后会失效；从工作区重新打开。

写入结果未知时保留原请求键，通过恢复/核对取得服务器结果。已经提交但界面未更新时刷新投影，不重新创建角色、生成任务或发布命令。旧审核请求的历史回执仍可核对，但新日常审核写入已退役。

## 其它运营工具

CMS 只读人员可以查看内容；有写权限的人员可以编辑字段、管理草稿与发布，高级 JSON 编辑仍可展开。Case 提供可阅读证据与选择框；无需把证据内部 ID 从其它页面抄进表单。

确认上线前检查实际用户展示、内容一致性和失败恢复。自动测试通过或预览能打开，不等于公开生产验收完成。
