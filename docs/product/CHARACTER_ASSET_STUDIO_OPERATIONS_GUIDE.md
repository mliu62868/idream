# Character Asset Studio 运营手册

更新于 2026-11-26，适用于角色创作者和发布运营。
入口：`/admin/characters/{characterId}?tab=assets`。
权威：[角色素材 ADR](../architecture/16-character-asset-studio-authority.md)；范围与实际限制：[当前覆盖](CURRENT_FUNCTIONAL_COVERAGE.md)；验收：[体检清单](ADMIN_PRODUCT_HEALTH_CHECKLIST.md)。

## 创作与发布

| 职责 | 流程与完成结果 |
| --- | --- |
| 角色创作 | 保存或修订私有草稿 → 建立身份和参考集 → 生成或上传图片 → 选齐三张展示图 → 无发布权时「记录创作交接」 |
| 发布运营 | 在「发布与预览」核对变更与 Main 预览 → 发布并查看自动技术检查结果 → 核对用户消费版本 |

两种职责可由同一有权限人员承担，写权限和生效时点分开。权限包按被分配的角色授予，每个包都能独立走完本职链路：

| 权限包 | 能做 | 不能做 |
| --- | --- | --- |
| `character_creator` | 改人设、读图库、生图与上传、设为身份 / 更换形象 / 参考集（`creative.run.read/write`、`content.official.write`）、选展示图、记录交接 | 发布、暂停、回滚 |
| `character_publisher` | 读图库（`creative.run.read`）、选展示图、发布 / 暂停 / 恢复 / 回滚、改精选（精选为全站排序，`content.read` 与 `content.featured.write` 为全局） | 生图 |
| `character_producer` | creator 的全部 + 发布 | 改精选 |

角色范围对所有权限生效：点名角色的请求逐项核对范围；不点名角色的生成记录列表、详情、搜索只返回范围内的数据，范围外一律 403。全局角色（admin、ops 等）不受影响。Today 对受限账号只列出、计数并允许认领被分配角色下的生成任务，非角色目标与范围外任务不可见。受限账号可读被分配角色图库的图片字节，并能读回自己提交的命令状态（命令状态按目标的读权限授权）。

交接不创建 Release、不切线上版本，也从不阻塞发布；只有能写项目但无发布权的账号看到「记录创作交接」按钮（选齐展示图后自动落到的发布页上也有），有发布权的人在发布页看到交接事实。需要改设定或新图时返回创作。日常不填写人工评分、逐图批准或五轮 QA；成年硬边界、基础拦截、文件/归属/来源检查及举报申诉继续有效。

## 工作区结构

角色详情按「概览 ｜ 设定（人设、外观与身份、声音）｜ 素材（图片、视频）｜ 上线（发布与预览、线上监控）」分组，`?tab=` 旧值兼容。头部常驻用户可达状态与草稿进度，概览只放下一步、未上线原因、最近素材与分发。标签与聊天工具在人设页独立小节，单独保存、不随发布。首次建立身份只在图片页（首张肖像）；「外观与身份」负责更换形象（建立新身份）与诊断，角色尚无身份时只给出前往图片页的入口。展示图三个位置统一称主肖像 / 角色主视觉 / 聊天场景图。

## 创建、身份与交接

1. 先填写成年角色的人设和开场，再填写视觉方向。复核和可选标签在保存前同页完成，保存后进入图片页。后续修改形成新内容版本，已发布快照保留。
2. 图片页首屏提供首张肖像生成、导入和图库入口。已有合格视觉身份的角色可直接采用合格图库图片。
3. 「设为角色身份」原子固定图片来源、视觉身份和参考集，同时记录草稿主图；不发布，也不授予线上槽位。身份与来源必须属于该角色。
4. 身份建立后，生成使用当前身份、参考集和已取得资格的路线，默认简报沿用角色视觉方向。手动生成可一次提交 1、2 或 4 张，每张在生成记录里有独立的单图 Run 和生成费用，整组请求可按原回执恢复。提交前显示「单价 × 张数 = 合计」，与接纳时记账同一计价函数；「生成缺失图片」显示上限（被跳过的展示位不计费）。图片页先提供可采用的候选，「生成缺失图片」只为仍缺合格候选的展示位各建一个 count=1 的 Run。
5. 人设和身份就绪后，可点「记录创作交接」。服务端保存当时的内容版本、身份、参考集和可选图片数。发布面板显示记录人、时间、可选图数量及内容、身份、参考集的变更。交接走 `POST /api/v2/admin/characters/:id/handoffs`。

复制角色从已有角色得到一份独立私有草稿；批量导入一次创建多个私有草稿。两者都只产生草稿，不发布、不继承公开资格。

参考集更新需匹配观察到的 active revision；冲突后读取当前版本，不能覆盖他人的新参考集。路线不支持完整参考或 source variation 时明确阻断，不能静默丢参考；「更多类似」需同时支持来源图与角色参考的实际能力。

## 图片库与槽位选择

生成和上传的同角色图片先入图片库，通过文件可用性、归属、真实来源及基础检查后可选择。上传保留上传证据，生成保留原 Run/Item/Job/Attempt 与参数；不得用当前模型或新槽位名称改写历史来源。默认创作用途只是构图起点，合格图片可选择到任一合适槽位。

- 肖像：脸部与身份清楚，用于发现卡片/头像。
- 详情大图：人物与场景传达人格和氛围。
- 聊天图片：符合角色开场语境，自然且身份连续。

三个槽位必须用三张不同图片。采用只更新带版本的草稿，不影响线上，也不复制素材或重新生成。候选发布版本存在时草稿被冻结；发布它，或在被拦的位置点「放弃候选并继续编辑」。发布校验失败的候选会自动撤回，草稿立即可编辑（见下文）。

创建向导可用一句话灵感或模板预填：只填空字段，部分失败时已生成的字段照常可用，模板选完即脱钩。向导选的标签随创建请求原子写入：标签不存在或无标签权限时角色也不会建出。列表页「导入」把 JSON 数组或带表头的 CSV/TSV 表格逐行建成私有草稿，失败行可重试，不自动发布。向导、导入与复制共用同一份视觉默认值：「一句话外貌」缺省时取第一条固定特征，绝不用简介；固定特征没有默认值。新建、复制与恢复的草稿都落在图片页。

列表可叠加生命周期和待办队列。详情的「返回角色搜索结果」回到同一查询的第一页。批量动作按目标给出回执，已完成的目标从选中项移除，失败项可重试。导入成功后当前列表立即刷新。

库中可搜索（文件名、标签、描述、日期）、看历史、维护标签与描述。卡片显示所占槽位，可直接用作封面/详情/聊天，可多选归档。归档、改私有或删除前检查所有身份/参考集、草稿、Look、Release、Run、投放/Campaign 等依赖；先在所属对象解除或替换依赖，批量全部成功或全部拒绝，原因选填。工作区「复制为新草稿」得到独立私有图片和文件，不继承公开资格、Release、Serving 与草稿选图，也不因源图片撤下而损坏；完整参考集可复制时一并复制当前身份，否则新角色从首张肖像开始。打开新草稿时一次性显示复制回执（复制/跳过的图片数、身份是否带上、需重新选的槽位）；源角色没有任何固定特征时拒绝复制并指向角色设置。

## 失败与恢复

生成中保留同一请求，等待 GPU 与实际执行分别计时；刷新不发新生成。失败保留已交付素材与来源，只对明确合格的失败重试；unknown 先恢复/核对，不能连续新建请求。自动超时失败但未实际退款，之后收到原任务有效产物时，可通过恢复入口采用原产物并保留失败记录；已实际退款或由运营确认失败的任务不自动改成功。费用见 [经济契约](ECONOMY_AND_PRICING.md)。

写入前保存原 intent/key；断网、刷新或另一个 tab 使用同一精确请求恢复。已接纳但界面未变时核对 command 与投影；401/403 不算终态。超过安全恢复期限仍未知时显式 reconcile，不无限自动重放。只有精确内容/身份/参考集/槽位与资产读回一致才解锁；不以相似图片或其它角色回执代替。

## 预览、发布与退出

「发布与预览」同页显示当前版本、草稿差异、缺图入口和 Main 的发现卡片、详情、开场及聊天图片。完整预览要求三个展示位各有一张可用且来源合格的图片。角色暂停时以当前发布版本为比较基准，草稿一致且发布资格有效时优先「恢复上线服务」。回滚回执标明新上线版本及内容来源。

准备发布冻结内容、身份、参考集、三槽位及各自来源，自动检查形成不可变候选。点击发布再次核验当前资格与真实 provider 来源，全部通过才原子更新 Release/Serving 与素材可见性；准备、校验成功不等于上线。任何槽位失败不留下部分线上副作用。发布校验失败（或快照无法投影）时，候选在同一事务内自动撤回（审计动作 `character.release.withdraw.automatic`），失败检查项与修复入口直接显示在发布页，刷新后仍从被撤回候选的校验结果读回；修复后再点发布会建新候选。版本 / Serving 冲突等环境性失败不撤回，可直接重试。

成功后核对工作区回执、Main 发现/详情/新会话、素材来源与账目；已有会话保持原 pin。暂停、恢复、回滚或 Serving 版本变化会永久撤销旧 live-preview token，即使恢复原 Release 也须重新打开。校验/监测政策更新时重新检查当前线上版本，旧通过记录不豁免新的来源与可用性规则。

- 草稿可归档并恢复为草稿，保留设定与素材。列表里「归档草稿」（可恢复）与「已退役」（发布过后永久退役，不可恢复）分为两个视图；批量「恢复草稿」只作用于归档草稿，已退役角色给出跳过原因。
- 暂停角色可直接退出运营，无需先恢复上线。
- 已上线版本通过暂停、恢复、回滚或退出命令处理，历史快照不可改写。暂停、恢复、恢复草稿单击执行；回滚和不可逆退役只有一个普通确认框。原因自动生成，无需填写。

## 视频、声音与运营效果

视频从明确选择的合法角色图片开始，仅在 capability、workflow/profile、环境、权益和报价允许时执行；显示真实阶段，刷新仍看原任务，文件可用并交付后可播放。技术交付不证明身份连续性或容量合格。声音可使用系统声音并试听；绑定、试听与用户 Chat 交付分别核验，低频克隆/身份工具按实际能力使用。声音激活、一键应用与重置立即对新会话生效，不进入 Release；声音页首屏显示当前线上声音，发布页列出这类不随发布的改动（声音、聊天素材「用于聊天」）。全平台默认声音只在「生成配置 → 默认声音」（`/admin/ops/profiles?tab=voice`，需 `generation.config.write`）修改，角色页只显示是否沿用系统默认。聊天素材启用需要媒体索引：索引未配置时「用于聊天」与批量发布直接禁用并说明，只能先存草稿；服务端因此拒绝时提示「没有启用、草稿不变」，不是「结果未知」。图片与视频失败使用同一套原因表达；视频重试在 Run 页执行，因为重试命令的幂等记录在那里。

运营效能从权威事实衡量：首张合格素材时间、创作交接及交接到上线时间、采用/变体采用比例、单张采用的真实 provider 成本、发布校验失败率及操作次数。先建立受控基线，再分风格/路线制定目标；不把生成张数或旧批准率当成功。不做单角色 A/B（规格未要求，且会破坏 Serving 唯一指针）；「新版是否更好」用 Release 前后对比回答。界面分离、模型资格、完整生成与公开发布仍需同 revision 操作证据，不由手册或自动测试认证。
