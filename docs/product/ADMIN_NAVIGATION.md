# Admin 导航与功能归属

更新于 2026-09-06。本文描述全局信息架构和交互契约；实现权威为 `packages/admin/src/components/admin/nav-config.tsx`，业务权限和命令仍由 Main 提供。

## 从任务推导结构

运营进入后台需要回答三个问题：现在要处理什么、要操作哪个业务对象、发生异常时去哪里恢复。因此首页承载待办，业务分组按对象与任务组织，平台运维和系统管理承载技术恢复与后台治理。实现模块、历史 URL 和团队职位不决定菜单分类。

角色是平台核心对象。创建、设定、角色素材、发布与单角色表现继续在角色工作台内完成；非角色宣传素材归内容运营，跨角色表现比较归数据分析。导航调整不增加发布审批、不改变 Main 的发布与计费权威。

| 一级入口 | 常规页面 | 按需展开的历史与专项工具 |
| --- | --- | --- |
| 今日工作 | 已授权待办与下一步操作 | 无 |
| 角色 | 角色、角色模板、分类体系 | 无 |
| 内容运营 | 运营素材、展示位、精选推荐、公告、站点内容与 SEO | 生成历史 |
| 用户与客服 | 工单、用户、账号请求 | 审核工单、客服工单、风控工单 |
| 收入与营销 | 订单与账务、定价、促销 | 无 |
| 数据分析 | 产品健康、角色表现、实验 | 无 |
| 平台运维 | 事故、数据一致性、生成任务、提供方、配置与灰度、提示配方、聊天运维 | 死信、后端诊断、生成健康、配置诊断、预设、工作流诊断 |

## 导航交互

- 今日工作直接打开首页，其余一级入口是展开按钮，固定图标，不借用第一个有权限页面的地址或图标。即使只有一个页面权限，分组语义也不改变。
- 分组标题常驻可见，当前分组默认展开；同一目录一次展开一个分组。具体页面是正常链接，可在新标签页打开。只有实际当前页带选中背景与 `aria-current="page"`；箭头只表示展开状态。
- 常规页面在分组内直接可见。工具单独展开；直接访问工具时，所属分组及工具区自动展开，目录滚动到当前项且不移动正文。只有工具权限的账号直接看到工具链接，不再增加一层空的常规／工具划分。
- 面包屑只说明位置，不承担隐藏的功能目录。全局搜索复用同一份页面名称、分组、URL 和权限谓词，支持中英文直达。
- 默认顺序为上表。专业工作模式只将相应任务提前，不成为第二套权限系统；系统管理始终在末尾。
- 桌面与移动抽屉复用同一导航组件。1200px 起显示固定侧栏；较窄视口使用抽屉，点击页面后关闭，支持 Escape、焦点圈定与关闭后焦点恢复。链接和按钮最小高度为 44px。

## 路由与授权

功能归属与 URL 独立。所有既有 canonical URL、兼容 URL、详情 ID、query 子视图和服务端路由继续有效。例如公告仍在 `/admin/growth/merchandising?view=announcements`，但显示在内容运营；账务仍在 `/admin/customer-ops/billing`，但显示在收入与营销。避免仅为菜单换名而迁移外部链接。

导航只展示满足页面完整 `read.allOf` 权限的目的地；无权限的深链接继续显示原有拒绝页与缺失权限。此次不改权限键、接口、数据库、写操作或发布策略。

## 验收范围

自动化验证覆盖功能与路由全集、不同工作模式下的授权集合、中文名称、页面标题与搜索一致性、query 切换恢复、只有工具权限的账号，以及移动抽屉的焦点与重复 ID。浏览器验证覆盖本地真实登录后的分组展开、页面跳转、桌面与窄屏导航。

本设计及验证范围是全局导航、功能归属和入口命名；各工作台内部业务流程的全面审计、真实生成、支付与公开发布需要各自的运行证据，不由导航测试替代。
