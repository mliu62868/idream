# 文档入口

本目录只保留仍能指导当前实现或解释可复核历史证据的文档。阅读顺序如下：

1. **产品与功能**：[`product/README.md`](product/README.md) → 用户结果、对象、功能与专题契约 → 对标、证据和剩余工作。
2. **工程架构**：[`architecture/README.md`](architecture/README.md) → 技术决策、模块边界、运行与测试；代码和同一 revision 的运行证据证明实际行为，不能据此取消产品需求。
3. **研究资料**：[`research/`](research/) → 外部资料与模型评估，仅在被产品或架构文档引用时影响决策。
4. **产品审计**：审计证据按 [`agents/audit-brief.md`](agents/audit-brief.md) 写进本地 `.scratch/<slug>/`，不进版本库。2026-09-13 前的历史审计证据（`docs/product-audits/`、`output/`）已移出工作树，需要时从 git 历史检索。
5. **专项技术记录与方案**：[`superpowers/`](superpowers/) → 尚需执行的方案或被研究/架构引用的独立技术记录；被现行契约覆盖的旧任务册删除。

## 维护规则

- 同一事实只在一个权威文档维护；其他文档只引用，不复制数值、状态或权限表。
- 完成或被取代且无独立价值的方案删除；有效要求合入现行契约，未闭合工作合入唯一剩余计划。原过程从 git 历史追溯，不创建归档副本。
- 每次整理后检查仓库内链接、日期、已退役术语和文档是否仍被入口索引。
- `AGENTS.md`、`CONTEXT.md` 与各目录 README 是协作入口，不在其他文档复制整套项目规则。
