# Alexa 角色图片生产：用户路径审计

日期：2026-07-21

范围：角色列表 → 角色概览 → 视觉身份 → 图片资产 → 准备图片生产。

用户目标：第一次使用时能快速完成必要设置；以后回来时能直接继续批次或创建更多图片。

## 总结

当前界面已经从“展示所有后台能力”进步到“给出单一下一步”，但状态模型仍然从系统技术就绪度出发，而不是从用户是否已经生产过图片出发。Alexa 已上线、已就绪并已有线上肖像，却仍被标成“首次设置”。这会让用户怀疑系统是否识别了已有成果。

最合理的体验不应只有“首次设置 / 创建更多”两态，而应至少区分：

1. 全新角色：创建首张身份肖像。
2. 已有线上图片但生产能力未启用：启用或修复图片生产。
3. 图片包未补齐：继续补齐图片。
4. 已有未完成批次：继续上次批次。
5. 已就绪：创建更多图片。

## 路径与健康度

### 1. 角色列表入口 — 需要修改

证据：`00-character-list.png`

- 优点：每个角色只有一个醒目的下一步入口，扫描成本低。
- 主要问题：Alexa 同时显示“已上线”“已就绪”“线上 1/3”和“首次设置”，状态语义冲突。
- 用户理解：这不是第一次使用，而是已有角色要补齐或启用后续生产。
- 建议：只在完全没有角色图片历史时使用“首次设置”；已有线上图时改成“启用图片生产”或“继续补齐图片”。

### 2. 角色概览 — 基本可用，但解释不足

证据：`01-project-entry.png`

- 优点：主标题和主按钮清楚；五步流程让用户知道整体方向。
- 主要问题：“图片生产暂不可用”没有在首屏说明原因、预计要做几件事，以及完成后的结果。
- 建议：将首屏改成任务摘要，例如“已有线上肖像，完成 1 次启用后即可创建更多图片”，并显示当前进度。

### 3. 视觉身份 — 不可作为新手引导

证据：`02-visual-setup.png`

- 主要问题：首屏同时展示多个等权重阻塞项、重复的“解决”和英文技术原因。
- 第一个“解决”链接指向当前已经打开的同一 URL，没有把用户带到具体表单或操作位置。
- 用户理解：能看出系统有问题，但不知道第一步实际要做什么。
- 建议：默认只显示一个可执行任务；技术诊断折叠到高级区域；每个操作必须跳到具体控件或直接完成可自动修复的动作。

### 4. 图片资产 — 方向正确，但动作定义不准确

证据：`03-image-assets.png`

- 优点：把七个技术阻塞压缩成“现在只做这一件事”，并说明现有线上图片不会变化，这是当前流程里最接近用户心智的页面。
- 主要问题：“准备图片生产”没有解释它会采用现有线上肖像、封存身份参考并尝试启用路线；用户不知道点击的影响。
- 建议：对已有线上肖像的角色，把按钮改为“使用现有肖像启用图片生产”，旁边用一句话解释不会修改线上图片。

### 5. 准备图片生产 — 阻塞

证据：`04-preparation-destination.png`

- 点击后仍停留在原页面，焦点留在原按钮，上方没有成功或失败结果。
- 页面 DOM 出现 `Admin authority request failed (500)`，但错误在当前视口之外，用户容易认为按钮没有反应。
- 建议：修复请求失败；错误必须出现在按钮附近，使用中文说明、重试入口和不丢失当前进度的保证。

## 优先级

1. P0：修复“准备图片生产”的 500，并提供就地错误恢复。
2. P0：把用户状态从两态升级为至少五态，禁止已有图片历史的角色显示“首次设置”。
3. P1：视觉身份页只展示一个当前任务，技术阻塞默认折叠。
4. P1：所有 CTA 使用结果导向文案；“解决”必须落到具体操作位置。
5. P1：对已就绪用户提供“继续上次批次”或“创建更多图片”，直接回到最近使用的图片用途。

## 可访问性观察与限制

- 已确认的优点：页面具有 tablist/tabpanel、region、heading、status 等结构；图片入口包含角色名及草稿/线上数量。
- 风险：中文页面混入英文技术错误；重复的短标签“解决”视觉上缺少上下文；请求失败后的可见反馈不在当前视口。
- 本次仅审计桌面视口和当前 Alexa 数据状态；未完成键盘全流程、屏幕阅读器、对比度数值和真实“创建更多图片”数据态验证，因此不构成完整无障碍合规结论。
