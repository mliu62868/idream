# Admin 角色工作流第一性原理复盘

日期：2026-08-27

## 审计范围

- 角色列表与创建入口
- 创建角色首步及创建完成后的去向
- 角色内设定、素材、运营
- 桌面与 390px 移动端
- 历史角色数据兼容失败

审计取证阶段没有提交角色、生成图片、发布版本或修改线上状态；随后仅修改 Admin 及其所需的 Admin API/契约来完成下述修复。

## 修复结果

本报告中的 Admin P1/P2 已于同日完成：

- 历史 `behaviorEvaluation` 不再使整个角色详情解码失败。
- 角色内素材分为图片、视频两个库；生成与外部导入是并列入口，未使用素材可移出。
- 运营在角色内直接为封面、主视觉、聊天场景选择已有图片；三个位置不能复用同一张图。
- 人工分数、质量勾选、批准、拒绝不再出现在角色图片与视频的真实素材入口。
- 创建角色仍从角色列表进入，完成后回到角色 Overview；Overview 的素材入口保持在角色上下文。
- Shared、Admin、Main 类型检查、相关单元/集成测试、定向 lint 与三个包构建均通过。
- 浏览器重新验证了角色列表、创建页、图片库、视频库和运营位；未提交创建、生成、导入、归档或发布操作。

本次实现只调整 Admin 与其所需的 Admin API/契约，没有改主站页面与用户流程。Chat/Agent 仍属于独立运行时问题域，不以本报告的 Admin 验证替代。

## 第一性原理

1. 运营的核心对象是角色，不是项目、Run、审核单或生成任务。
2. 创建角色只负责建立一个私密角色草稿；素材创作负责增加可用素材；运营负责从现有素材中决定用户看到什么。
3. 生成和外部导入只是素材进入角色素材库的两种来源，不应产生两套资产管理流程。
4. 素材可以删除或归档；已被线上位置使用的素材必须先替换。
5. 不需要人工质量审核、批准、拒绝工作流。运营的真实决定只有“使用、替换、移除、生成更多”。
6. Admin 的调整不得改变主站角色、聊天或三个现有图片位置的用户体验。

## 步骤与健康度

### 1. 角色列表 — 健康

证据：`01-character-list.png`

- 角色是明确主对象，“创建角色”只有一个入口。
- 状态筛选、搜索、排序和每卡一个下一动作满足 MVP。
- 风险：多数线上角色仍被 Journey 投影为“继续补齐图片资产包”，使创作任务压过真实运营状态。

### 2. 创建角色 — 基本健康，需要解耦

证据：`02-create-character.png`

- 三步只回答角色是谁、长什么样、确认创建；比旧商业简报流程更符合 MVP。
- 最终动作仍是“保存角色并打开肖像工作台”，创建完成后强制进入创作。
- 保存状态 `Not saved` 未本地化。

### 3. 角色设定 — 健康，有一个边界泄漏

证据：`03-character-settings.png`

- `设定 / 素材 / 运营` 一级结构正确，Overview、Soul、视觉身份、声音分组合理。
- 当前状态与最近素材为运营提供必要背景。
- “查看全部”跳到通用 `/admin/creative/library?targetId=...`，离开角色上下文；与“素材库属于角色”不一致。

### 4. 角色素材 — 不符合已确认的产品模型

证据：`04-character-assets.png`、`07-character-assets-mobile.png`

- 页面主任务仍是“新图片”，角色素材库只是生成工作台左侧输入。
- 没有角色内外部导入、删除/归档入口。
- 候选图必须经过分数、质量勾选、批准/拒绝，再能进入草稿图片包。
- 这把素材管理、生成、质量审核和运营选择重新耦合在一个页面，与已确认的 MVP 决策相反。
- 390px 无横向溢出，但大图占据首屏，生成和素材动作被推到更深位置。

### 5. 角色运营 — 信息架构正确，能力模型错误

证据：`05-character-operations.png`

- 上线预览、发布版本、线上运营的分组是对的。
- 当前运营页面只告诉运营“图片包不完整”，然后送回素材生成流程。
- 运营不能针对主肖像、角色主视觉、聊天场景三个现有位置直接从角色素材库选择或替换图片。
- 因此创作仍是运营的强依赖，而不是一个可选素材来源。

### 6. 历史角色详情 — 阻塞

证据：`06-character-detail-validation-failure.png`

- 素材齐全的 Mara Vale Launch 无法打开详情。
- 历史 `behaviorEvaluation` 的 gate 与当前 schema 不一致，导致整个 Character Workspace 解码失败。
- 页面直接展示英文 Zod 错误；“重试”不能解决数据契约不兼容。

### 7. 移动端 — 结构健康，任务优先级仍错误

证据：`07-character-assets-mobile.png`

- 390px 下一级区域、二级页面选择器和内容顺序可用，`scrollWidth === clientWidth === 390`。
- 素材大图占满首屏，管理与创作动作需要较长滚动；这是桌面产品模型问题在移动端的放大，而不是单纯响应式问题。

## 优先级建议

### P1 — 先修

1. 历史行为评测证据必须降级为“旧证据/需重新检查”，不能让它使整个角色详情不可用；UI 不再直出 schema 错误。
2. 重做角色素材页的任务模型：素材库为主体，生成与导入为两个入口，图片卡只提供使用、替换、移除/归档、生成相似图。
3. 把三个图片位置的选择移到运营页。运营点击“替换”后从角色素材库选择；不触发生成，也不要求批准/拒绝。

### P2 — 随后收口

4. 创建角色成功后落到角色 Overview；卡片再给“创建首张肖像”下一动作，不强制打开肖像工作台。
5. 角色 Overview 的“查看全部”回到角色内素材页，而不是通用素材中心。
6. 删除 Admin 中分数、质量勾选、批准、拒绝、superseding rejection 等人工审图流程；保留后台不可变生成记录即可。
7. 本地化创建页保存状态，并将错误恢复文案改成运营可执行动作。

## 可访问性

- 已确认：一级区域有 group 与 pressed 状态；二级页面有 tablist/tabpanel；移动端使用具名 select；页面无横向溢出。
- 风险：历史数据错误虽然是 `role=alert`，但会向辅助技术完整播报内部英文 schema；禁用的“检查”tab 暴露了无法解释的状态；移动端核心素材动作离首屏较远。
- 未验证：颜色对比、浏览器缩放、完整键盘回路和真实屏幕阅读器体验；截图与 DOM 证据不足以宣称 WCAG 合规。
