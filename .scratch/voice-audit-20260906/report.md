# Admin 角色音色复制与默认音色审计

日期：2026-09-06。结论：基础模型合理，原实现存在真实的可用性、显示与恢复问题；本轮已修复，并完成声音范围内的真实 Admin 操作与媒体交付验证。

## 合理的设计与保留的约束

- 系统默认用于没有已启用角色音色的角色；角色专属音色固定 provider 与音色身份。
- 参考音频复制和官方目录选择都先生成候选，再试听、显式启用。创建候选不会改变当前声音。
- 启用、恢复默认和修改系统默认仅影响之后新生成的语音。旧消息继续重放已交付音频，避免声音漂移及重复计费。
- 默认 Pocket TTS 提供英语音色，Fish Audio 提供参考音频复制，两者应能同时工作。Fish 演绎参数不应用于 Pocket。
- 全站默认在独立折叠区操作，要求对应权限、变更原因、全局作用范围确认及版本校验。

## 已发现并修复的问题

| 原问题 | 改进与验证 |
| --- | --- |
| Fish 作为复制 provider 时，Admin 官方 Pocket 选声入口消失，后端也拒绝创建 | 复制与官方目录分别检查运行时；两个入口并列可用，故障相互隔离 |
| Pocket 候选被 Fish 复制服务的状态阻止启用 | 候选就绪状态按其持久化 provider 检查；真实创建与启用成功 |
| 更改“系统回退音色”会暗中覆写 female/male/trans | 四个独立映射，改变回退值保留其他三个，明确当前角色使用哪项 |
| “线上试听”使用尚未保存的演绎参数 | 线上试听固定已保存设置；编辑区试听独立标识，版本/参数过期时不展示旧试听 |
| 同一试听同时渲染两个自动播放音频元素 | 线上/编辑区按试听用途分别显示，回归断言只出现一个 autoplay 元素 |
| 保存默认失败后确认框仍关闭，原因丢失 | 错误传回对话框，保留原因，并以同一幂等键重试 |
| Pocket 当前声音被错误标记为“性感”等 Fish 演绎 | 展示真实 provider 与原生演绎；复制运行时单独标识，不冒充当前播放线路 |
| 成功命令在 provider 故障或配置变更后无法重放 | 成功回执优先，配置与健康校验仅阻止新操作；重放不再次创建/扣费 |
| 数据库已提交但回执丢失时，异常清理可能删除已提交音色/音频 | 清理先等待同一 Character 行锁，再读取提交事实；数据库不可读时保留资源、告警并保留原始错误 |
| 连续创建超过 20 个候选后，旧 active 被历史分页挤出 | active/candidate 独立查询，历史仍限制 20 条；正确显示当前音色 |
| 只读默认映射仍可编辑，多个按钮同时显示无关“正在克隆” | 权限控制选择框；各操作使用各自忙碌提示；官方试听文案与复制文案/原因分离 |

## 证据、清理与限制

- `final-live-evidence.json`：请求/attempt/provider/profile/default版本、媒体 SHA-256、usage fact、全局默认保存及 Admin 审计记录。
- `live-*.json` / `clip-*.log`：每次 HTTP 状态、耗时和原始结果；`pocket.wav`、`fish.wav`、`default.wav` 为交付验证副本。
- `source-manifest.json`：本轮最终相关源文件 SHA-256。运行方式为 Next 开发服务从源码编译/Fast Refresh；PM2 启动时的 revision 不是本次变更的不可变发布证明，不将其当作 production certification。
- 私有验证角色已归档，验证账号标记 audit 并暂停，临时登录会话与额度授权均已清除。保留私有归档音色/媒体及审计证据，不清理已有角色或旧失败记录。开发库全局默认保留已验证的同一 Alba 有效映射 version 2。
- 本轮验证的是音色业务链路与可靠性，未评价每个音色的主观吸引力、复制相似度评分或长文本/多并发性能。Pocket 的英语边界仍存在，不代表中文语音已获验证；英语之外可使用经试听确认的 Fish 角色音色。
- 当前三类默认仍都是 Alba。代码允许这样配置，但对角色差异化不理想；现在可以分别设置性别默认、或给角色启用自己的官方/复制音色，不应凭音色名称猜测声音特征后批量替换现有配置。
- 保留任务开始时已有的 Admin 导航及其他未提交变更；未提交、未推送本轮代码。
