# 明确并补齐账号验证与访问恢复

Type: task
Priority: P0
Status: needs-info
Requirements: AC-02

用户失去密码或原会话后，应能理解并完成受支持的验证和恢复路径。当前一次性恢复码可用，但不能据此宣布验证码重发/过期处理及无恢复码时的访问恢复目标已经完成。

**当前可复现边界**

[account-access.ts:76](/Users/kk/code/idream/packages/main/src/server/modules/ourdream/account-access.ts:76) 要求邮箱、预存恢复码和新密码，成功后撤销旧 session 并更换恢复码；`:120` 的重发要求已登录且知道当前密码。这是恢复码轮换，没有邮件验证码发送/重发链。现有 [PRD AC-02](/Users/kk/code/idream/docs/product/PRD.md:284) 仍要求验证码重发/过期、访问恢复和会话失效说明；当前没有产品决定说明恢复码已替代该需求。

**需要的信息**

需明确账号验证与找回的产品契约：邮件验证码的使用时机及与恢复码的关系；失去密码且未保存/已失去恢复码时采用何种可验证的自助或客服恢复路径。若选择有意偏离邮件验证，须记录明确决定、任务等价证据与不能恢复的边界，不能从现有代码反推业务需求已被废除。若保留邮件路径，其生产送达和服务凭证纳入 [08](/Users/kk/code/idream/.scratch/product-audit-20260910/issues/08-public-production-certification.md) 的外部认证；已有恢复码和账号隔离验证可先行。

**预期行为与真正退出条件**

1. 明确 AC-02 每一用户任务的实现路径及 `matched/equivalent/intentional_divergence` 结论，保留需求来源和产品决定。恢复码的成功演示不能单独关闭邮件验证码/无恢复码访问恢复缺口。
2. 若采用邮件验证码，真实收信并完成申请、重发、冷却/限流、过期、一次使用、旧码失效、失败重试和 session 失效提示；若采用经明确决定的等价路径，逐项证明同样的账号归属与访问恢复目标，说明用户失去全部凭据时的可用支持和实际结果。
3. 受控账号验证恢复码失效/重放/轮换、旧 session 撤销、并发和未知响应可恢复；错误账户/凭据不能登录或泄露另一个账号资产，不能以硬编码成功或绕过身份校验关闭事项。
4. Chrome 验证登录失效、注册/恢复后的合法返回路径，以及切换账号后草稿、媒体、余额、待核对请求分别隔离；恢复访问不自动再次执行付费动作。保留本轮已经通过的隔离回归，仅补验未覆盖的路径。
